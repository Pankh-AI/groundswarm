Incident ID: CS-2026-0729-4. Starting at 02:50 UTC on 2026-07-29, a single storage node in Cobalt Storage's eu-central-1 cluster began returning elevated read latency after a failing disk began retrying reads at the hardware level, a degradation that was not caught by the node's health check because the disk had not yet failed outright. Approximately 3% of read requests routed to that node experienced latency above 2 seconds, versus a normal p99 of 80 milliseconds, for a duration of 51 minutes. No write requests were affected, and no data was lost, since Cobalt Storage replicates all objects across three nodes. The degraded node was identified through per-node latency percentile alerting at 03:31 UTC and drained from the read path at 03:41 UTC; the physical disk was replaced during a maintenance window the same day. Cobalt Storage is lowering its node health-check latency threshold and adding an automatic drain trigger for any node exceeding p99 read latency of 500 milliseconds for more than 5 minutes.
