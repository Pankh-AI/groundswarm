OSS Packaging & Monetization Landscape

Product-pivot research, thread 1 of 2 · compiled 2026-08-15 · background research agent, model sonnet, 4 tool-call batches
Three questions for the OSS-SDK-first pivot: how do comparable frameworks actually package and distribute themselves (declarative config vs. code-only), what does the open-core monetization path look like in practice (star counts and time-to-revenue, not folklore), and does anything already combine a declarative swarm-config surface with independent live-source verification — which would blunt Groundswarm's differentiation story. Answers: packaging splits roughly evenly between declarative and code-only; monetization needs far fewer stars than intuition suggests but tracks workload trust bar, not company quality; and nothing found combines both properties — a genuine, currently-open packaging-axis finding, not just the already-established verification-axis one.

1. Packaging & declarative-config survey

FrameworkInstall / CLIDeclarative configNotes
swarms (kyegomez)pip install swarms; run-agents --yaml-file Yes — zero-code Strongest story checked: one YAML defines both the agents: list and a swarm_architecture: block (swarm_type: Sequential/Concurrent/AgentRearrange/MixtureOfAgents/auto). run-agents --yaml-file agents.yaml builds and executes it — no Python file required at all, confirmed against source (pydantic SwarmConfig/AgentConfig). Apache-2.0. Release-tag hygiene is stale (last GitHub tag Dec 2024) even though PyPI ships weekly to 14.0.0.
CrewAIpip install crewai; crewai create crew Yes, thin glue needed Two generations, both shipped: current default is JSON (crew.jsonc); --classic gives the original agents.yaml + tasks.yaml pair, loaded via a @CrewBase-decorated crew.py. Even the YAML path needs minimal Python glue — not truly zero-code. MIT core; CrewAI AMP is the paid managed/self-hosted tier.
AutoGen / AutoGen Studiopip install autogenstudio (separate package) Only in a non-production side-app Core autogen-agentchat is code-only. Studio's "Team Builder" offers declarative JSON team specs + drag-and-drop, but docs say it "is not meant to be a production-ready app." Framework itself has been Microsoft-declared maintenance-mode since Oct 2025 (last release 2025-09-30); GA successor is Microsoft Agent Framework. Original creators forked as AG2, actively maintained.
LangGraphpip install langgraph; langgraph-cli No langgraph.json is a deployment/build manifest, not a swarm schema — it just points at a compiled graph object in code. Docs: "graph nodes, edges, and logic remain in your application code." Very high release cadence (~1-3 weeks).
camel-ai (CAMEL)pip install camel-ai, no core CLI No Workforce orchestration primitive is code-only (.add_single_agent_worker() etc.), no YAML schema found. Companion desktop app Eigent (OSS, Apache-2.0) wraps Workforce in a GUI, not a checked-in config file.
OpenHands (ex-OpenDevin)pip install openhands-ai; agent-canvas No Repositioned in 2026 around Agent Canvas, a self-hosted control center for coding agents. Legacy config.toml (now explicitly V0/deprecated) configured single-session runtime settings, not a multi-agent pipeline. No declarative multi-agent swarm config anywhere in the current stack.
DeepEvalpip install deepeval; deepeval test run No — deliberate choice Eval suites are Python test files (wraps pytest). A third-party comparison explicitly credits Promptfoo, not DeepEval, as the declarative-YAML-eval-suite tool in this space.
Ragaspip install ragas; ragas quickstart No Metrics defined in Python. Momentum flag unrelated to packaging: last release Jan 2026, last commit to main Feb 2026 — ~5.5 months stalled as of this survey, 30 open PRs, moved to a new org (vibrantlabsai) now pitching paid consultations on the README.
Two frameworks outside the original checklist surfaced during the search and are worth folding into the competitive set: PraisonAI (real declarative agents.yaml multi-agent workflow config) and Haystack (official Pipeline.dumps()/loads() YAML serialization).
Cross-cutting pattern: declarative-config support splits roughly 3-for/5-against among the eight originally checked — swarms and CrewAI ship real YAML/JSON swarm definitions (swarms is zero-code, CrewAI needs a thin Python entry point); AutoGen only offers it in a deprecated, non-production side-app; LangGraph, camel-ai, OpenHands, DeepEval, Ragas are code-only, confirmed by direct source/doc inspection rather than assumed from reputation. A config/YAML-first surface is a real, viable packaging choice in this space — not a novel bet — but it isn't the default either.

2. Open-core monetization playbook (8 comparable cases)

CompanyOSS → first paid signalStars at that pointFree/paid cut line
PostHogSeed raised 20202.8k — lowest of any case Usage-based pricing on the hosted product, not a discrete enterprise-features tier. ~$50M ARR (Oct 2025) → $57.5M (Feb 2026), targeting $100M by end of 2026.
Airbyte$150M Series B ($1.5B valuation)5k SSO/RBAC/audit logging withheld from OSS entirely, not offered as a paid add-on to an otherwise complete free product — stricter cut line than most. Zero-to-unicorn in under 2 years.
DeepEval / Confident AIPaid platform launched ~1yr after OSS release (2024) 3.3k (Oct 2024) → 17.6k now Verified from pricing page: OSS self-hosted unlimited; Starter $200/mo adds no-code eval workflows; Team $2,000/mo is where SSO/custom RBAC/SOC2 turn on; Enterprise adds on-prem/HIPAA. $2.2M seed (YC W25) closed in 5 days. Closest license precedent to Groundswarm (Apache-2.0) and ADR-003's cited case.
PrefectFirst paying Cloud customer 4 months after OSS launch— Fastest OSS-to-first-customer gap found. $11.5M Series A → $32M Series B four months later. Notably moved a UI feature from paid to free over time.
n8n162k stars now — an order of magnitude above every other case— Not OSI-approved open source — self-coined "fair-code" Sustainable Use License, free to self-host but explicitly bans running it as a competing hosted service. A materially different protection mechanism than Groundswarm's Apache-2.0 choice, which forgoes that protection.
DagsterCloud reached GA 4 years after founding— Slowest of the data-orchestration peers. $33M Series B narrative led with growth multipliers (active projects tripled, contributor activity doubled in 12 months), not star count.
Temporal$200M+ raised through Series C ($1.72B valuation, Mar 2025)— Pricing gates identity features as a distinct paid step: Essentials $100/mo, but SAML SSO only turns on at the $500/mo Business tier — unavailable below that at any price.
HashiCorpMost successful open-core conversion pre-2023 (FY2021 rev $212M)— Cautionary case, with a specific lesson. Aug 2023 BSL relicensing (retroactive) triggered a 33k-star fork-threat repo within a month, a governed fork (OpenTofu) within six weeks, new-customer growth slowing to 1.5% QoQ, a $20M guidance cut, 8% layoff — then IBM's $6.4B acquisition 8 months later. Lesson: never retroactively change licensing once external teams depend on the original terms — directly relevant since ADR-003 commits to Apache-2.0 at launch, not a later relicense.
Synthesis:
  1. Absolute star count needed before money arrives is much lower than intuition suggests. Every non-stalled company monetized in the low thousands of stars (PostHog 2.8k, Airbyte 5k, DeepEval 3.3k), not tens of thousands. Stars are a lagging indicator, not a gate.
  2. What actually preceded money in every case was a specific concrete usage signal, not a star-count milestone: a named company already in production asking for something the OSS version doesn't provide (Prefect), a self-reported download number (DeepEval), a measured community-activity multiplier over a fixed window (Dagster). For Groundswarm, the signal to watch for is a specific team already running extraction+verification swarms in production and asking for SSO/audit/hosting.
  3. Time-to-paid-tier (4 months to 4 years) tracks workload trust bar, not company quality. Dev/CI-adjacent tools (Prefect, n8n, Airbyte, Confident AI) monetized in months; production-critical infra (Dagster, Temporal, Terraform) took years. An extraction+verification swarm feeding downstream decisions sits closer to the Dagster/Temporal end — a multi-year gap to first serious revenue should be treated as the normal case, not a failure signal.
  4. The free/paid cut line was uniform across every non-stalled case: managed hosting, seat/team scaling, SSO/RBAC/SCIM, audit logging, compliance certs, support SLAs are what's gated; nobody withheld core functionality long-term. This validates ADR-003's plan exactly — no new information changes that decision, this is confirmation, not correction.

3. Combo check: declarative config + independent live-source verification

Eight distinct search angles (framework-agnostic terms, the frameworks above, PraisonAI, Haystack, gpt-researcher, academic factuality tools FacTool/SAFE/MACE, n8n). Nothing found combines both properties as a shipped, built-in feature. The two capabilities live in disjoint tool categories:
  • Frameworks with real declarative YAML/JSON swarm config (CrewAI, PraisonAI, Haystack, swarms) are general orchestration tools with no built-in claim/citation re-verification against live sources — any fact-checking pipeline built on them is user-assembled on top, not a shipped feature.
  • Tools that do independent live-source re-verification (FacTool, SAFE/DeepMind, MACE, Tool-MAD) are code-only academic research artifacts with no swarm-config surface at all.
  • Closest partial match: gpt-researcher has a narrower config.json and genuinely fetches/cites live sources — but it verifies while generating, not as an after-the-fact re-verification of an already-extracted claim, which is exactly the distinction that matters for Groundswarm's positioning.
This is a genuine, currently-open packaging-axis finding as of 2026-08-15 (standard caveat: a negative search result proves non-discoverability, not non-existence). It strengthens the differentiation story already established in the market survey (no verification-company checked does swarm-combined, live-refetched verification either): the gap isn't just uncaptured on the verification axis, it's uncaptured on the packaging axis too, and Groundswarm's config/YAML-first, verification-native combination would be first to occupy both at once.
