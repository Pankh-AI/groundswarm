Groundswarm — Project Hub

Open source · early / architecture & research phase · last updated 2026-08-18
A swarm of OpenClaw-based agents, coordinated by a new orchestrator, whose combined output is independently re-checked against live primary sources before anything is reported as fact. Not SwarmBench, not a fork of any proprietary task-package format, built on OpenClaw (MIT) as the worker runtime plus a new orchestrator and verifier of Groundswarm's own. See README for the full pitch and LICENSE for terms.

Status

⚠ Early — architecture and licensing decisions made, orchestrator, verifier and memory not yet implemented beyond the single-domain capstone prototype the verification pattern was proven on. Literature survey, market survey, SWOT, similar-projects, name-availability, and memory-landscape research completed 2026-08-13; see audit log for the full run record. Published as Pankh-AI company work, Copyright 2026 Pankh-AI, under an existing Pankh-AI GitHub org. The first proof-case domain (vendor infrastructure incident monitoring) is now confirmed (2026-08-18, ADR-005) — it's the domain every measured result in this repo already ran against, so this just names what the evidence already committed to. A fourth component, Memory, a scoped and verified shared knowledge store, has been added to the architecture (ADR-007), checked against 9 agent-memory products and 2 research proposals, and confirmed as a genuine, unaddressed gap, not yet built. See decisions. Product pivot underway 2026-08-15: open-source SDK/framework first, config/YAML-based swarm definition, no UI for v1 — schema designed, loader not yet written. The Move-2 "Verified Beats Plausible" benchmark, run as a parallel, non-gating workstream, now has a measured result (2026-08-16, ADR-017): verification catches 39/40 injected bad claims across two live runs at zero false-rejection cost, both unverified baselines leak 40/40. See Move 2 results. The N-worker scale sweep was also extended to N=200 (2026-08-16) against a live remote endpoint, finding and fixing a second real crash-class bug (a worker echoing prompt schema text into the quote field as a dict); fail-closed held with zero false confirms on the clean re-run. See N-worker sweep. OpenClaw integration re-architected 2026-08-17 (ADR-018, supersedes ADR-001): cloning and reading OpenClaw's real source showed it's a single always-on Gateway daemon, not a spawn-per-worker binary, so Groundswarm now manages the Gateway's full lifecycle and dispatches through its real agent-backed chat-completions endpoint. First live smoke test passed: 3 source-grounded claims through a genuine agent turn on local Ollama, after finding and fixing two real OpenClaw-side bugs. See OpenClaw Gateway integration. The verification-outcome feedback loop is now built and run live (2026-08-18, ADR-019): a full 5-worker pipeline run through the real Gateway (27 claims, 18 confirmed) flagged its worst performer and re-dispatched it with a caution note generated from the Verifier's own tally. The first version of that re-dispatch came back byte-for-byte identical to the original — root-caused, by reading the Gateway's own log, to same-session reuse anchoring the agent on repeating its first answer, not to the prompt content. Fixed by giving each dispatch attempt its own Gateway session; the in-product re-run then showed a genuinely different response and confirmed claims went 0/4 → 3/3, with the honest caveat that isolating the caution note's own effect from fresh-session sampling variance is still open, scoped as follow-up. See OpenClaw feedback loop. CLI-backed worker execution landed and was calibrated live 2026-08-18 (ADR-020): workers can now route extraction through a real Codex CLI or Claude Code CLI subprocess instead of the local Ollama GPU, via OpenClaw's own harness config. Both harnesses verified against real backends — claude_cli: 5 workers, 64 claims, 100% confirmed; codex under real ChatGPT-subscription auth (no API key): 5 workers, 45 claims, 100% confirmed — after finding and fixing two real config-mutation bugs (timeout defaults too tight for a live model-catalog lookup, and an API-key SecretRef written even when subscription auth needed none). See CLI harness calibration. Not yet measured: whether either CLI harness actually beats local Ollama on speed/quality for this workload, and Orchestrator.synth_client still stays Ollama-only regardless of worker backend.
