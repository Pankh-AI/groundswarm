Limitations

What this research round does and does not establish
This page exists so the SWOT and market survey don't get read as more settled than they are. Four specific gaps, and one process note on what wasn't looked up and why.

No benchmark validates the core bet

The literature survey found no existing benchmark that scores "genuinely grounded vs. merely plausible" for multi-agent output specifically. The strongest evidence Groundswarm's approach works is the internal capstone prototype (63 claims, 41 checks, tested against real and deliberately empty submissions), not a peer-reviewed or third-party result. That's a real gap between "the idea is validated" and "the idea is unrefuted so far."

Fail-closed judging is confirmed hard, not solved

AbstentionBench (cited in the literature survey) found abstention does not improve with model scale, models keep guessing when they should decline. This means the verifier's deterministic re-fetch/round-trip layer has to carry the real weight of "fail closed," the LLM judge is a secondary check, not the primary guarantee. Treating the LLM judge as sufficient on its own would contradict the literature this project is building on.

Trademark clearance is incomplete

The name-availability check (GitHub, npm, PyPI, web search, DNS) came back clear, but no formal USPTO/EUIPO/WIPO trademark database search was run. That matters more once the planned Enterprise edition is real revenue, not before. See similar-projects research for exactly what was and wasn't checked.

Memory component is a confirmed gap, not built code

The competitive check against Mem0, Letta, Zep/Graphiti, LangMem, CrewAI, Cognee, Mastra, and two managed cloud offerings (see memory landscape research) found no product or research proposal combines Memory's five design properties. That's evidence the design targets a real gap, not evidence the design works, none of it is implemented yet, and "no existing product does this" is not the same claim as "this will work when built." The gap is real; the execution risk is still entirely ahead of it.

Enterprise pricing/feature detail is genuinely thin

Several competitors (Patronus, HoneyHive, OpenHands Enterprise) don't publish pricing or full feature scope; the market survey reports what's publicly available, not a complete picture. Any competitive claim about "Groundswarm Enterprise vs. X Enterprise" made later should re-verify against current public info rather than reuse this snapshot.

Quote round-trip proves the evidence is real, not that it supports the claim

quote_round_trips() (verifier/checks.py) only checks that claim.quote appears verbatim in the source. It does not check that the quote actually entails claim.text. A claim like text="Meridian Cache stores passwords in plaintext" paired with quote="Meridian Cache" (a real two-word substring of any Meridian Cache postmortem) would currently pass the deterministic check, because the check only asks "does this text exist in the source," never "does this text support that claim." This hasn't shown up in the swarm runs so far because the model tends to quote genuinely relevant spans, not because anything stops it from doing otherwise. This is the same distinction the "EVIDENCE_VALID vs CLAIM_VALID" gate split targets, and it's a real, currently-unguarded gap, not a hypothetical one, first confirmed while responding to a request to build math/numeric verification.

GitHub portfolio cross-check deliberately not performed

The original research request included checking the project owner's own GitHub activity for relevant context. No GitHub remote is configured on this local repository, and pursuing this further would have meant either guessing a public identity from a common name or using git-config-derived personal data that was flagged as sensitive and out of scope for this research. Deferred pending an actual public handle supplied directly, not attempted here. No personal identifying information was used in, or is present in, any file on this page or elsewhere in this research round.
